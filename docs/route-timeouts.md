# 路由超时配置

在路由编辑弹窗的“传输与超时”中设置，保存草稿并发布后生效。配置、版本及导出均使用 JSON；旧配置未包含新增字段时继续使用原有默认值。

| 配置项 | JSON 字段 | 默认值 | 生效范围 |
| --- | --- | --- | --- |
| 处理超时 | timeoutSeconds | 60 秒 | 普通请求的总处理时长；流式模式和 WebSocket 不应用此限制 |
| 后端连接超时 | connectTimeoutSeconds | 5 秒 | DNS 查询与全部后端 IP 的 TCP 连接尝试共用该预算 |
| TLS 握手超时 | tlsHandshakeTimeoutSeconds | 5 秒 | 连接 HTTPS 后端的 TLS 握手 |
| 响应头等待超时 | responseHeaderTimeoutSeconds | 30 秒 | 请求发送完毕后等待后端响应头，不限制正文读取 |

所有字段均为整数秒，允许 0–86400，0 表示使用默认值而非无限等待。普通请求同时受到总处理预算与阶段预算约束，以先到期者为准。例如处理超时 60 秒而响应头等待 120 秒，普通请求仍会在总预算到期时结束。

流式/SSE 应启用“流式 / 长连接模式”，避免长时间输出受到普通请求总处理预算限制。WebSocket 自动免除总时长限制，但完成协议升级前仍受连接、TLS 握手及响应头预算约束；升级后的消息传输不使用响应头超时。当前不提供流式正文或 WebSocket 消息的空闲超时。

响应头发送给客户端前，连接、握手、响应头等待或总预算超时返回 504。响应正文已经开始时不能改写状态码，代理会中止传输，客户端应按不完整响应处理。连接拒绝等非超时错误仍返回 502。

同一后端池中，具有相同阶段超时设置的路由复用连接池，不同设置隔离；不会在处理请求时修改共享 Transport。健康探测继续使用独立的 3 秒请求预算，不随路由超时变化。

超时配置不改变业务监听端口、管理入口或现有静态目录授权。
