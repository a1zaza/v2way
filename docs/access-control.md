# 站点登录路由与 IP 授权

客户端直接连接 v2way，来源仅取连接的 `RemoteAddr`，不读取转发头。访问码在各站点配置中独立生成，登录页由各站点的路由规则提供，访问码、IP 白名单、续期及撤销均按站点隔离。

## 配置与使用

1. 打开“站点配置”，为本站启用 HTTPS，填写业务端口并配置有效证书。
2. 展开“访问策略与请求限额”，在“本站访问码”中确认登录域名及路径；通配站点填写实际访问域名。
3. 点击“生成访问码”。若本站还没有登录路由，按钮显示“生成访问码并添加登录路由”，会将对应的 `access_login` 精确路由添加到本地编辑，默认路径 `/access` 可先修改。已有登录路由时直接使用该路由，不重复添加。
4. 点击“复制链接及访问码”复制两行内容：`链接: …`、`访问码: …`（8 位随机数字）。访问码只在这次弹窗中显示，关闭后不回显，遗失时重新生成。
5. 要限制业务访问，开启“需要 IP 登录授权”，保留编辑、保存草稿并发布。访问码生成即时保存，路由及站点配置发布后链接才生效；界面区分已发布链接和草稿链接。
6. 用户打开 `https://本站域名:HTTPS端口/登录路径`，输入本站 8 位数字访问码，明文显示，无需用户名或密码。443 端口可以省略。系统设置只保留授权记录的查询、筛选和撤销，不再设置访问码。

也可以先在路由规则中手动添加“IP 授权登录页”动作。每站点最多一条非根精确登录路由，使用 GET/POST，登录路径及子路径保留给认证与字体资源；已有父级代理兜底可保留。

访问码使用密码学安全随机数生成，按字符串保留前导零。输入框为明文文本，使用数字键盘并校验恰好 8 位 ASCII 数字，前后空格、字母、全角数字、重复字段和旧用户名/密码表单均不作为访问码接受。已有 8 位数字密码可直接作为访问码使用，不再校验旧用户名；更早的非数字密码需重新生成访问码，已有授权保持有效。

访问码生成不自动开启站点保护，也不自动发布。取消站点编辑不会撤销已经成功生成的访问码；在新站点尚未发布时，访问码不会使任何业务入口提前开放。

访问本站任一绑定域名的登录路由都属于同一站点授权。其他站点即使使用相同路径、相同 IP 或相同域名的不同端口，也不会共享授权。新生成的访问码各站点独立；A 站点的访问码不用于 B 站点，重新生成 A 不改变 B。

登录路由不进入业务后端，也不出现在普通网站导航中。未授权访问其他业务路由返回 404，不自动跳转或泄露登录路径。登录必须使用 HTTPS；HTTP 访问登录路径返回 404，未知 SNI 仍拒绝 TLS 握手。

登录路径可自行选择，无需系统生成随机地址；路径本身不是认证凭据。页面使用项目本地字体，不依赖第三方资源。删除或变更路由后，旧版新式表单提交带有的内部标记会阻止凭据落入业务兜底路由。

## 隔离、续期与访问策略

- 授权键为“站点 ID + 规范化 IP”，单个 IPv4/IPv6 精确匹配，不包含来源端口；IPv4-mapped IPv6 转为 IPv4。
- 首次登录授权 48 小时。同站点有效授权下的正常业务访问得到 2xx/3xx 后，续期至本次访问后的 48 小时；304、业务重定向和成功的 WebSocket 101 计入。
- SSE/WebSocket 在有效期内传输数据可续期。A 站点的访问只续期 A，不延长 B；连续 48 小时没有本站正常活动则需重新登录。
- 浏览登录页面、状态查看、字体资源、内部健康探测、ACME 挑战、未保护站点、未匹配路径、4xx/5xx、访问拒绝和网关 HTTPS 升级跳转不续期。外部监控访问正常业务路由成功时，按普通业务请求处理。
- 已过期、已撤销或重新登录替换的旧记录，不能被慢请求或存量连接复活。
- 原有静态 IP 白名单/黑名单、站点限流、证书检查仍生效。登录路由只豁免动态 IP 授权，不能绕过静态策略；本站进入维护状态后包括登录页在内都返回 503，不影响其他站点。
- 受保护响应强制 `Cache-Control: private, no-store`；后端或路由无法改为公共缓存。已交付客户端的数据不远程删除。

同一出口 IP 下的设备在同一站点共享授权；不同站点仍隔离。网络变化后重新登录。入口和业务访问使用不同 IPv4/IPv6 地址时分别授权。本功能不替代应用自身的账号与权限。

## 部署网络与登录来源校验

默认 Compose 使用 host 网络，不配置 ports。业务端口按已发布站点配置直接监听宿主网络，默认绑定 `0.0.0.0`；管理 HTTP 默认只监听宿主回环 `127.0.0.1:4033`。发布新业务端口无需追加映射，部署者核对占用及防火墙。host 网络共享宿主网络，`127.0.0.1` 可用于连接宿主服务；前置代理或 NAT 仍可能改变来源 IP。

以下端口映射说明适用于自定义 bridge 部署，默认 host 配置无需这些映射。

登录页也支持不同端口映射，例如 `443:8443` 或 `9443:8443`：站点配置填容器监听端口 8443，分别通过 `https://本站域名/access` 或 `https://本站域名:9443/access` 访问。业务站点按容器实际监听端口、请求域名及 TLS SNI 匹配；登录来源按浏览器实际发送的 Host（含外部端口）计算，不拿容器端口代替。默认 443 会规范化为无端口来源，IPv6 地址保留方括号。TLS 仍由 v2way 的业务站点终止。

控制台生成的链接与 HTTP 升级 HTTPS 的目标端口仍依据站点配置，无法自动知道 Docker 的外部映射。使用不同端口映射时，分享登录链接需改为实际外部端口，并直接访问 HTTPS；若需要直接使用自动生成链接和 HTTP 跳转，采用相同端口映射。

登录页设置 `Referrer-Policy: same-origin`，保留同源表单提交的 Origin，并阻止向跨源目标发送 Referer。`no-referrer` 会使浏览器普通表单 POST 的 Origin 变成 `null`，从而误拒绝合法登录。登录、撤销始终要求 Origin 与当前 HTTPS 来源完全一致；缺失、`null`、跨域、跨协议或跨端口均拒绝，仍验证 Cookie、CSRF、站点与来源 IP，不退回 Referer 校验。

来源 IP 继续只取 `RemoteAddr`，不信任 `Forwarded`、`X-Forwarded-For`、`X-Real-IP` 或转发 Host/端口/协议头。Docker bridge 端口映射本身不会提供可信的应用层转发头。经 userland proxy、IPv6 转 IPv4、宿主机回环、NAT 回流或其他网络转发时，连接对端可能变为 Docker 网关或其他中间地址，具体以部署路径为准。若多个客户端被转换成同一 IP，它们在同站点会共享授权，应用无法从已经转换的连接恢复原 IP。

部署后从宿主机之外的两台设备打开登录页，核对页面“当前 IP”与预期出口 IP；再登录一台，在系统设置核对授权记录，并确认另一出口地址不会被放行。相同公网出口下的设备共享授权属于本功能的既有行为。IPv4 与 IPv6 访问应分别确认；若不同出口设备都显示同一 Docker 网关 IP，需要部署侧提供保留源 IP 的网络路径，不能通过信任任意转发头修复。

Docker 官方说明：[端口发布与映射](https://docs.docker.com/engine/network/port-publishing/)、[bridge 网络](https://docs.docker.com/engine/network/drivers/bridge/)；回环 userland proxy 的来源地址差异见 [Docker 文档问题讨论](https://github.com/docker/docs/issues/17312)。本项目通过本机真实 TLS 监听与目的连接重定向覆盖同端口、外部默认 443 和外部非默认端口的登录、授权与撤销；该测试模拟端口映射的应用层效果，不代表已在实际 Docker 网络中验收。

## 管理与撤销

系统设置显示授权归属站点、IP、授权时间、最近活动和预计到期时间，支持按站点筛选、IP 搜索和分页，每页 50 条。数量是站点-IP 授权记录数，同一 IP 在两个站点授权时计为两条。

单条撤销只影响该记录所属站点，不影响其他站点相同 IP。重置访问码保留已有本站 IP 授权：授权 ID、授权时间、最近活动和到期时间不变，不因重置自动延期，原连接可继续正常续期，过期记录不会复活。授权记录的内部关联及修订同步更新，保持 JSON 校验与重启恢复有效；旧访问码不能再用于新增登录。需要取消访问时请显式撤销记录或清空授权；停用访问码仍会撤销本站授权。系统设置的“清空授权”撤销所有站点授权。这些操作同步持久化并即时生效，不等待业务发布。

业务访问日志列表、请求详情和搜索支持来源 IP；IP 授权审计及管理员登录、草稿保存/导入、配置发布/回滚、管理账号修改、站点访问码生成和撤销授权等已有审计事件附带独立 `ip` 字段。来源仅取请求的 `RemoteAddr`，移除端口并规范化 IPv4-mapped IPv6，不信任客户端转发头。旧日志或没有请求上下文的本地操作不补造 IP；内部代理或 Docker 转换来源时只能记录实际连接对端。业务日志仍仅保留最近 1000 条内存记录，审计随月度 JSONL 保存。

授权与访问码更新/停用审计展示站点名称，例如“站点「文档站」授权来源 IP …”，独立 `siteId` 字段保留内部关联。新日志记录事件发生时的名称，优先取已发布配置，未发布站点取草稿；旧日志在查询显示时按当前配置解析名称，不重写历史文件。站点不存在或名称无法解析时回退内部 ID。

记录使用不可变随机 ID，续期不改变该 ID；重新登录产生新 ID，旧操作不能误撤销新授权。清空使用集合修订校验，并发新增时需刷新并重新确认。

登录成功后的 10 分钟表单上下文可撤销本站当前 IP，其他浏览器即使共享出口也须重新验证访问码。Cookie 名按站点区分，限定路径，设置 Secure、HttpOnly、SameSite，并绑定站点、来源 IP、Origin 和 CSRF。它不与控制台会话混用。

撤销或到期不主动中断既有 SSE/WebSocket，但后续数据不能恢复记录；新请求立即检查最新状态。取消保护、删除站点或进入维护后，该站点旧连接不再续期。

## JSON 与升级兼容

登录页是 `Site.routes` 中 `action: "access_login"` 的路由；保护仍使用 `Site.requireIpLogin`。两者保存草稿并发布后生效，不增加启动参数或全局端口。

`.data/access-control.json`（权限 0600）使用 schemaVersion 3，按站点保存账号摘要及授权集合，最多 8192 个账号条目、4096 条有效 IP 授权。明文访问码不写入 JSON、草稿、日志或浏览器持久化存储。访问码元数据接口不返回明文，生成接口仅在持久化成功后返回当次 code 字段。它不进入普通配置导出，也不随业务版本回滚。内部沿用 schema 3 的 account/passwordHash 字段保存 Argon2id 摘要，username 仅保留兼容关联，新生成使用固定内部标签，不再作为登录输入或复制内容。管理控制台仍使用独立的管理员用户名与密码。

自动续期每 60 秒合并写入，正常关闭最终刷盘；异常退出可能丢失最后一个尚未落盘周期的活动，重启不补足有效期。同步授权/撤销写失败不会返回成功；结果未知时停止新授权并拒绝动态放行，使用系统设置的持久化确认流程恢复。文件损坏不会被自动覆盖，未保护站点与管理入口保持可用。

从旧全局隐藏入口版本升级时：

- schema 1/2 的旧统一账号仅迁移到已有受保护/登录站点及原站点授权记录对应的站点，保留原密码摘要；迁移后各站点账号独立。新建站点不继承旧统一账号，需要自行生成。
- schema 1 的全局 IP 授权仍丢弃；schema 2 已有的本站 IP 授权在原站点保留，不扩散到其他站点。重新生成本站账号保留已有授权及有效期。
- 旧运行配置与历史快照中的 `accessGate` 字段仅为读取兼容保留，旧全局入口不再处理登录。旧的受保护站点在添加本站登录路由并发布前保持拒绝访问，不自动解除保护。
- 控制台在本地编辑时移除旧入口字段；为每个受保护站点添加路由后保存并发布。直接发布或回滚旧全局入口格式会被校验拒绝，需先作为草稿调整。
- 不手改已有运行文件或历史摘要，不自动重置账号。本次代码更新本身不修改实际数据，格式转换在服务下次加载私有授权文件时进入内存，随后按正常安全写入或刷盘持久化。

原始功能设计与历史记录见 [IP 授权设计](ip-access-gate-design.md)。
