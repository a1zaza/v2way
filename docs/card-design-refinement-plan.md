# v2way 卡片视觉修订方案

- 日期：2026-11-04（Asia/Shanghai）。
- 状态：方案待确认；本轮只审查和编写方案，不修改产品代码、样式、接口或数据。
- 范围：站点管理、路由规则、后端服务和证书管理。
- 基线：上一轮卡片优化实施后的当前代码。本方案修订其视觉与默认信息组织方式，保留已经修正的健康、草稿、超时和签发状态逻辑。

## 1. 复查方法与结论

复核 `card-components.tsx`、`object-cards.tsx`、`records.tsx` 及相关 CSS，并用普通长度的模拟名称、域名和路由重新生成桌面与手机静态截图：四类卡片 × 1440px/390px，共八组。此前极长内容截图用于补充边界判断。

这些是静态组件夹具，使用当前真实 CSS，但不包含完整应用导航和数据轮询；本轮没有启动开发服务、执行生产构建或访问真实数据。

上一轮改善了信息完整性、状态准确性与溢出保护，但默认卡片仍承载过多详情和解释。常规数据下，站点桌面卡片尚能保持简洁；路由卡片明显更像一个只读表单，手机证书卡片则呈现纵向堆叠的按钮与状态。需要调整内容取舍及排布，单纯改颜色或间距无法解决全部问题。

**推荐方向：卡片负责快速识别和常用操作，完整参数集中到自定义详情弹窗。**

## 2. 已确认的视觉问题

| 问题 | 当前表现和代码依据 | 影响 |
| --- | --- | --- |
| 头部容易形成多层缩进 | `CardHeading` 将名称、展开按钮和副标题放在同一列；窄卡片状态又被放到第二列下一行 | 图标旁边堆叠多行，状态与正文左边缘不一致 |
| 容器断点触发过早 | 380px 容器查询依据内容盒宽度；加上卡片左右内边距，外宽约 420px 的桌面卡片也可能进入窄布局 | 常见尺寸下名称、副标题、状态频繁从一行变成三层 |
| 字符数决定展开按钮 | `ExpandableText` 按 32/70 字符判断，未判断实际是否超出可见区域 | 能放下的内容也可能出现按钮，短于阈值的文字则可能自然换成多行，卡片节奏不稳定 |
| 辅助按钮散落正文 | 长名称、域名、节点、目标、超时各自可能带一个展开按钮 | 边框元素过多，信息和操作争夺注意力 |
| 路由默认信息过密 | 五个键值行后还有站点状态、连接模式、总预算说明和阶段超时按钮 | 卡片接近配置摘要表，快速比较路径与目标反而困难 |
| 后端提示重复 | 每张卡片都有“健康摘要对应已发布版本”等完整说明 | 多卡片时重复文字占据空间，真正的异常信息不够突出 |
| 证书操作被强制分行 | 窄布局下 `.certificate-actions > .card-disclosure` 被设置为整行宽度 | 390px 视口中，即使两个按钮可以同排，指纹与续期仍上下堆叠 |
| 详情展开改变整排高度 | 正文和底部的展开区都直接增加卡片高度；网格同行卡片随最高项拉伸 | 展开一个对象会让相邻对象出现明显留白，操作区位置跳动 |
| 徽标与边框数量偏多 | 图标底框、域名标签、状态徽标、连接模式徽标、各类展开按钮同时出现 | 卡片视觉碎片化，主要状态不容易一眼识别 |

“没有横向溢出”只说明布局没有破损，不能证明阅读节奏、密度和视觉层级已经合适。本次实施后的验收需增加普通数据对照，不能只依赖极长内容和尺寸检测。

## 3. 建议保留的部分

- 深灰主题、蓝色强调、细边框和现有品牌风格。
- 主体最大宽度 1600px、自动列数和单卡最大宽度 520px。
- 文字操作使用有背景和边框的标准按钮，桌面至少 34px、手机至少 44px。
- 未修改显示原状态，有修改才显示草稿；不改变保存与发布流程。
- 已发布健康记录与草稿节点分开判断，空记录不显示正常。
- 实际超时默认值、流式总时长豁免和续期防重复提交逻辑。
- 当前发布时间展示方式，继续用内部编号执行发布和回滚校验。

## 4. 新的卡片骨架

### 4.1 头部：名称与一个主要标识

- 图标缩小至约 16px，容器约 24px，降低独立底框的视觉重量。
- 名称占主要空间，最多两行；主要状态或动作类型位于右上角，顶部对齐。
- 移除标题内部的“展开完整内容”按钮，完整名称放入“查看详情”弹窗。名称的可访问标签保留完整文本。
- 非必要的副标题移到正文或辅助行，避免名称下面继续堆叠域名数量、规则序号等小字。
- 不再对所有内容盒小于 380px 的卡片强制换状态行。只有真正放不下时才换行，换行后状态与正文左边缘对齐。
- 窄布局阈值建议先试内容盒约 260–280px，再结合 320px 手机视口验证；该值是待验证参数，不直接作为最终定值。

### 4.2 正文：默认三至四行核心信息

正文使用一致的标签与内容对齐方式，但不把所有配置项都放入键值表。路径、地址可以显示两行，其余内容尽量一行。

普通名称、域名或路径按实际可用宽度省略，完整值在详情中可查看和复制。不以悬浮提示作为唯一查看方式，也不按字符数制造额外按钮。

### 4.3 辅助行：只显示有价值的摘要

- 正常默认参数不逐项重复解释。
- 普通状态使用文字，避免每条辅助信息都包成徽标。
- 草稿、异常、即将过期、签发中等需要注意的状态保留明确文字和适度颜色。
- 共享说明放在页面级说明中，例如健康数据来自已发布配置；单卡只显示“2 个待发布节点”等对象相关信息。

### 4.4 底部：稳定的标准按钮组

- 每张卡片最多两个主要文字按钮；删除图标单独靠右。
- 按钮能同排时保持同排，只有实际宽度不足才换行，不按证书类型强制堆叠。
- 不在底部直接展开长文本或指纹，避免操作区高度随详情变化。
- 不把整个卡片变成可点击按钮，不依赖 hover 才出现操作。

## 5. 四类卡片的具体取舍

| 页面 | 头部主要标识 | 默认正文 | 辅助行 | 底部按钮 |
| --- | --- | --- | --- | --- |
| 站点 | 启用／停用，或草稿状态 | 主域名、业务入口、路由数量 | 其余域名数量；必要的配置提示 | 站点配置、查看详情、删除图标 |
| 路由 | 动作类型 | 所属站点、匹配方式与路径、HTTP 方法、目标摘要 | 流式／自定义超时／所属站点草稿等简短文字 | 编辑规则、查看详情、删除图标 |
| 后端池 | 运行健康摘要 | 调度方式及节点数量、最多三个节点的精简预览 | 待发布节点数或缺失健康数据数 | 编辑后端池、查看详情、删除图标 |
| 证书 | 有效期状态 | 证书来源与环境、主域名、到期时间 | 自动续期状态、正在签发或结果需检查 | 查看详情；ACME 另有立即续期 |

### 5.1 站点管理

- 主域名改为直接可读的等宽文本，避免把所有域名都渲染成带框标签。
- 默认只显示主域名与“另有 N 个域名”的摘要，完整域名进入详情。
- 路由数量可保留快捷跳转能力，放在“查看详情”内提供“查看路由规则”标准按钮，避免卡片底部出现三个文字按钮。
- 默认请求体上限不常驻正文，放入详情；存在需要关注的异常配置时才增加提示。

此处明确建议调整上一轮的“三个域名预览”规则：域名改为一个主域名加数量摘要。后端节点仍保留最多三个，采用更紧凑的行布局。

### 5.2 路由规则

- 合并“匹配方式”和“匹配路径”，例如“前缀 /api”，减少一个独立键值行。
- HTTP 方法仍完整表达“全部方法”或指定方法；不因精简改变匹配含义。
- 目标显示当前动作对应的摘要：后端池名称、静态路径、响应状态或跳转地址。
- 移除默认的阶段超时展开按钮及每卡重复的 WebSocket 解释。自定义超时显示一条摘要，完整总预算和阶段值进入详情。
- 站点状态注明来源，使用“站点草稿待发布”等简短文字；不将其伪装成路由自身的独立启停状态。
- 规则序号放入详情，只用于定位，不暗示执行优先级。

### 5.3 后端服务

- 每个预览节点优先占一至两行：地址一行，状态与权重一行；长地址在可见区域内省略，详情提供完整文本和复制。
- 移除每个节点地址自己的展开按钮以及节点列表后的独立“查看其余目标”按钮，统一进入详情。
- 健康汇总继续按已发布节点计算；草稿目标、当前运行目标在详情中明确区分。
- 页面级说明解释健康数据来源，卡片内只保留与该对象相关的变更或异常摘要。

### 5.4 证书管理

- 证书来源及测试／正式环境放入正文；测试证书不受浏览器信任的提示保持可见。
- 域名与站点统一为主域名加数量，不铺开多个标签。
- 保留精确到期时间及剩余小时提示，但避免同一状态在头部、正文和辅助区重复三次。
- “查看证书指纹”合并为“查看详情”，指纹与复制功能进入详情弹窗。
- ACME 证书的“查看详情”和“立即续期”优先并排；手动证书只有“查看详情”，不增加空按钮占位。
- 排队／签发中只保留一个清晰状态表达，续期按钮禁用；不再同时在多处重复“签发处理中”。

## 6. 详情弹窗

复用现有自定义 `Modal`，新增只读对象详情模式，不引入新的侧栏或弹窗库。

详情内容包括：

- 完整名称和对象信息。
- 全部域名、节点、路径和可复制字段。
- 路由有效超时、请求头及完整目标。
- 后端运行健康与草稿差异的必要说明。
- 证书指纹、续期状态和有效期信息。

数据来自当前已经加载的对象及任务快照，不为查看详情新增后端写接口。若某个字段当前没有数据，显示明确缺失状态，不推测值。

查看详情不修改草稿、不触发发布或签发。弹窗继续支持键盘焦点管理、关闭恢复焦点、正文滚动与手机短横屏；编辑入口关闭只读详情后打开现有编辑框，避免叠加两层活动弹窗。

保留站点到路由列表的跳转入口。删除、恢复签发结果等操作继续采用现有流程，不塞进只读详情作为新的隐式动作。

## 7. 视觉参数与实施约束

- 卡片外框仍使用当前 6px 圆角和细边框，不增加阴影或渐变。
- 标题约 14px，核心正文 13px，辅助信息 12px；用位置和字重区分层级。
- 图标降低装饰重量；每张卡片只保留一个最主要的徽标，其他信息优先使用普通文本。
- 卡片内边距保持桌面 20px、手机 16px；分区间距建议控制在 12–16px。
- 不强制四类卡片相同高度，也不增加固定高度的卡片内部滚动条；同页同排底部自然对齐。
- 不恢复文字链接式操作按钮。减少按钮数量，通过合并入口解决视觉拥挤。
- 保留当前共享组件的合理部分，调整 `CardHeading`、默认正文和详情入口职责；避免继续给每类卡片追加覆盖样式。

## 8. 实施顺序

1. 先完成站点与证书的普通数据静态样稿，对照 340/400/520px 卡片宽度和手机视口，确认头部与底部的节奏。
2. 实现只读详情弹窗，将分散的名称、域名、节点、指纹和超时展开入口合并。
3. 精简路由与后端默认正文，保留状态计算与操作保护。
4. 清理旧展开区与强制换行规则，完成交互及响应式回归。

本轮仅输出方案。获得实施授权后再修改产品代码，不直接沿用上一轮“所有参数都展示”的默认结构。

## 9. 验收重点

### 视觉对照

- 首先比较普通数据的折叠态，再检查极长名称、多域名、多节点和异常状态。
- 覆盖单卡、不满行、满行与多行；检查 320/390px 手机、常用桌面及超宽屏。
- 单独验证容器宽度临界点，不能只验证视口断点。
- 头部不再出现图标旁的连续按钮／副标题／状态堆叠；证书按钮能容纳时同排。
- 默认卡片中无散落的字段展开按钮，不因查看详情撑高整排卡片。
- 在保持无溢出的同时，人工审查行数、留白、徽标数量和普通状态下的高度。

### 交互和逻辑

- 完整名称、域名、地址、指纹和超时均可通过详情查看，不能因为精简而丢失访问入口。
- 查看详情、编辑、站点路由跳转、复制、删除确认和续期均保留。
- 草稿、运行健康、测试证书、超时默认值及续期防重复提交保持当前正确语义。
- 详情关闭后焦点恢复；手机上按钮至少 44px，键盘焦点与可访问名称清晰。

### 验证边界

本次八组截图确认了当前的视觉问题，不是新方案的实现验收。实施后的测试应同时覆盖静态布局和真实 React 交互；模拟数据不能代替真实业务联调，也不为本方案擅自启动开发服务或执行构建。
