# 后端流量统计

后端服务卡片展示请求数、上行流量和下行流量，取代重复的“被动检测与失败恢复”说明。健康检测配置与说明保留在编辑后端池表单中。

## 统计口径

- 按后端池 ID 汇总，共用后端池的所有站点和路由合并累计，不按目标节点拆分。
- 请求进入代理动作时计数；没有健康节点、连接失败等代理尝试也计入。代理之前被访问策略拦截的请求、固定响应、静态文件及重定向不计入。
- 上行是代理读取的请求正文，下行是代理读取的后端响应正文；网关自行生成的错误正文不计入。健康检查请求及其正文均不计入。
- SSE 等流式正文在读取期间持续累计；WebSocket 握手计为一次请求，升级后的双向隧道字节持续累计，包含帧开销。
- 不统计 HTTP 头、TLS 及底层网络开销；HTTP 传输层透明解压等行为可能使正文统计不同于实际网络流量。此数据用于运行观察，不是网卡计量或流量计费依据。

## 生命周期与页面显示

数据仅保存在进程内存，不写入配置 JSON，不提供历史时间段查询。进程重启清零。同一 ID 的后端池连续发布时保留累计，存量流式连接的流量仍计入；发布删除该池后再重新加入时重新计数。草稿校验不改变统计。

管理 API 的 `GET /api/admin/v1/overview` 提供 `upstreamStats`，以运行中的后端池 ID 为键，每项包含 `requests`、`uploadBytes`、`downloadBytes`。控制台沿用每 5 秒的概览轮询，多个计数为实时采样，不承诺同一时刻的原子快照。

已发布且有运行数据的后端池显示累计值，即使草稿存在修改，数据仍对应已发布的运行配置；未发布或数据不可用显示 `—`，已发布但尚未收到请求显示 `0` 和 `0 B`。流量按 B、KiB、MiB、GiB、TiB 等二进制单位显示。

## 访问日志中的响应体积

访问日志的 `bytes` 按单次请求记录下行字节，普通 HTTP 为写出的响应正文；WebSocket 等升级连接为写向客户端的隧道字节，包含 WebSocket 帧开销，排除握手 HTTP 头。上行数据不计入这个字段。

升级连接的最终访问日志在连接结束后写入；连接存续期间可通过后端卡片查看持续累计的上下行流量。关闭连接时会等待正在进行的下行写入完成计数，部分写入只记录实际写出的字节；发布配置不会使存量连接的日志计数丢失。
