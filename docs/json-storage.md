# JSON 存储与恢复

v2way 正常运行不使用 SQLite；新实例不会生成数据库。JSON 文件通过同目录临时文件、文件同步、原子替换及父目录同步写入，适用于本机 Linux 文件系统。数据目录必须独占，不支持共享盘多实例写入，也没有自动监听人工文件编辑。

## 文件与提交

- `storage.json`：格式版本及转换完成标记。
- `gateway.json`：唯一的配置提交点，首次发布后生成；配置摘要、发布记录和历史索引随配置一起保存。
- `versions/`：不可覆盖的版本快照，当前版本和最近 100 个历史；未提交候选不进入正常回滚列表。
- `draft.json`：草稿、修订和基础版本；保存、导入均不改变运行配置。
- `account.json`：管理员与 Argon2id 摘要，密码保持原有规则；会话仅保存令牌摘要到有界内存，重启需重新登录。
- `logs/audit-YYYY-MM.jsonl`：月度审计，单月最多 16 MiB，启动时清理当月及前两个月以外的文件。审计失败不会否认已完成的配置提交，状态显示告警。启动只自动修剪最后一个日志文件的不完整尾行，中间损坏需人工处理。
- `certificates/`、`acme/`、`master.key`：既有加密材料。普通网站配置导出不包含这些秘密，也不是完整备份。

发布先校验配置和运行资源、预占新增监听端口，再持久化历史候选及运行文件，最后激活内存快照及监听计划。端口占用和权限错误发生在提交前；提交失败释放预占端口。修订和预期运行版本均须匹配；重试保持原请求标识及参数。若替换完成但目录同步失败，API 返回 503 / `result_unknown`，保留旧内存快照并冻结后续写入。通过系统设置“确认文件持久化状态”重新同步和激活，或正常停止后重新启动确认磁盘状态；不能随意重复提交新请求标识。

运行文件损坏拒绝启动；历史损坏时保留当前服务并停止配置写入；草稿损坏可在控制台显式从运行配置重建，原文件保留副本。文件在运行中被外部修改会导致冲突，不自动覆盖。

## 配置导入

控制台“配置版本”或“系统设置”可以选择文件、粘贴原始 JSON，支持纯 `sites` / `upstreams` 或完整运行快照。完整快照只提取业务配置，不接管外部发布版本、历史索引或账号。输入限制 8 MiB、64 层，拒绝重复键、未知字段、尾随内容和不支持的格式。

离线命令也会获取实例锁：

```bash
go run ./cmd/v2way check -file examples/gateway.json
go run ./cmd/v2way import -data .data -file examples/gateway.json
```

`check` 只检查配置结构和语义；`import` 只更新草稿，仍需在控制台检查运行资源并发布。运行中的实例请用管理页面导入。

## 一次性旧库转换

1. 正常停止后端，保留完整原数据目录及原 `master.key`。不要重新初始化账号。
2. 使用 Python 标准库离线备份和导出；不安装数据库驱动，也不修改原库：

```bash
python3 tools/export_sqlite.py --data .data --output .data/legacy-export.json
go run ./cmd/v2way migrate -data .data -file .data/legacy-export.json
```

导出工具获取排他锁，使用 SQLite backup API 生成一致数据库备份，并复制证书、密钥等文件到 `backups/sqlite-*`。导出文件权限 0600，包含密码摘要和加密材料，按秘密保护。转换保留账号摘要、草稿修订、最多 101 个成功版本、审计和证书；原数据库不删除，登录会话不迁移。已有加密 JSON 证书优先保留。转换中断仅允许同一导出文件继续；完成标记最后写入，禁止覆盖已经完成的实例。

3. 启动新后端，重新登录，检查草稿、运行版本和证书。确认以前不要删除原库、导出文件和备份。正常运行不会读取原库；后续 JSON 变更不会同步回旧库，不能直接启动旧程序作为无损回退。

## 显式历史恢复

停止后端并完整备份目录后选择已知版本：

```bash
go run ./cmd/v2way recover -data .data -version 7
```

静态站点需同时传入与启动时一致的 `-static-root`；业务协议与端口来自所选快照。命令获取排他锁、校验所选快照和运行资源，将当前文件及历史复制到 `backups/recovery-*`，再以新的递增版本提交所选配置。不会自动猜测应恢复哪个版本。重启后核对运行状态；草稿独立保留。

完整备份必须正常停机后复制整个数据目录，保护 `master.key` 和账户文件。运行中跨多个文件复制不保证一致性。当前尚未提供完整加密备份包、真实断电及全容量故障验证。
