# ACME 免费证书签发与续期

v2way 支持通过 ACME 接入 Let’s Encrypt，提供 HTTP-01、DNS-01、测试/正式环境、异步任务、自动续期和证书热更新。手动上传仍可使用。

## 控制台操作

1. 打开“证书管理 → 申请免费证书”。
2. 输入证书名称、联系邮箱和域名列表。
3. 选择 HTTP-01 或 DNS-01；DNS-01 还需选择服务商并填写凭据。
4. 首次建议选择测试环境，确认验证流程可用后再新建正式环境申请。**测试证书不受浏览器信任**，测试和正式 CA 的账户按环境隔离。
5. 同意 Let’s Encrypt 服务条款并提交，页面显示排队、验证、签发、成功或失败状态。
6. 签发成功后，在站点配置选择证书，保存并发布。首次签发不自动创建站点或修改业务路由。

控制台申请使用稳定的请求标识，网络重试复用同一任务；同一标识使用不同参数会被拒绝。同一证书不能并发执行多个任务。

## HTTP-01 条件

- 域名需要由公网 DNS 正确解析，公网验证请求必须能够访问该域名的 **80 端口**。
- 将 `/.well-known/acme-challenge/` 路径转发至 v2way 的业务 HTTP 监听器。先发布带 HTTP 端口的站点，转发到该端口；系统不自动创建 80/8080 等业务监听。若尚未配置 HTTP，可先创建只启用 HTTP 的站点，签发后再启用 HTTPS。公网端口映射由部署者安排。
- 挑战路径只响应正在验证的域名与令牌，优先于普通站点匹配、访问策略与 HTTPS 跳转；未知令牌返回 404。
- 前端开发端口 `5173` 和管理 API 端口 `4033` 不能替代业务挑战入口。
- HTTP-01 不支持通配符申请；`*.example.com` 必须选择 DNS-01。

本功能不会自行以管理员权限绑定 80 端口，也不会自动更改宿主防火墙或已有入口。

## DNS-01 服务商

| 服务商标识 | 控制台名称 | 必填凭据 |
| --- | --- | --- |
| `cloudflare` | Cloudflare | DNS API 令牌；可选独立的区域读取令牌 |
| `tencentcloud` | 腾讯云 DNSPod | 腾讯云 SecretId、SecretKey；可选区域及临时会话令牌 |
| `alidns` | 阿里云 DNS | AccessKey ID、AccessKey Secret；可选 STS 令牌 |
| `digitalocean` | DigitalOcean | API 令牌 |
| `linode` | Linode / Akamai | API 令牌 |
| `rfc2136` | RFC 2136 / 自建 DNS | 更新服务器、DNS 区域、TSIG 密钥名称及 Base64 密钥 |

Cloudflare 令牌需要目标区域的 Zone:Read 与 DNS:Edit 权限。腾讯云使用云 API 密钥，**不接受旧版 DNSPod 的 ID,Token 登录令牌**。RFC 2136 默认使用 `hmac-sha256`，也可选择 `hmac-sha512`。

DNS-01 支持普通域名及通配符。网站可仅在内网运行，但验证使用的域名必须有可查询的公开 DNS，网关也必须能访问 CA、服务商 API 及权威 DNS。

创建 TXT 后，程序查询权威 DNS，确认所有返回的权威服务器均能看到本次值，再通知 CA 验证。DNS 传播最多等待 10 分钟，整项任务最多 15 分钟；服务商 HTTP API 有独立超时。

Cloudflare、腾讯云、阿里云、DigitalOcean 和 Linode 保存本次创建的记录 ID，清理时仅删除对应记录。RFC 2136 使用匹配 TXT 值的删除操作，不清空同名 TXT 集合。记录标识随订单恢复材料加密保存，正常失败和恢复时均尝试清理。

部分第三方适配器会对整个同名 TXT 集合或记录集执行清理，本版没有直接采用这些适配器。后续新增服务商需要同时实现创建、按记录精确删除、恢复及测试，不仅增加一个下拉选项。

## 续期与热更新

- 申请时可启用自动续期；也可在证书卡片点击“立即续期”。自动续期按申请时保存的环境、域名和凭据运行。
- 启动时及此后每小时检查一次。当剩余有效期进入证书总有效期的后三分之一时续期，窗口最长 30 天。
- 续期成功沿用证书标识，原子保存新材料并更新内存缓存。新 TLS 握手使用新证书，已有连接保持；无需再次发布站点配置。
- 失败不覆盖现有证书。一般失败采用退避，下一次尝试时间显示在任务数据中；CA 的 Retry-After 较长时遵守该等待时间。
- 若签发最终结果或落盘状态不能确定，显示“结果待确认”，停止对该证书的自动重试；点击“检查并重试”时先查询已保存的订单，已签发则取回原证书，避免再次签发。
- 重启将未完成任务标记为中断，不自动重放。手动恢复复用原订单和私钥，并清理已记录的 TXT；确认原订单无效后才创建新订单。

更换 DNS 凭据、切换 CA 环境或调整证书域名，目前通过新建申请、成功后切换站点引用完成；本版不提供旧申请配置的在线修改或凭据回显。

## 文件保存与兼容边界

```text
.data/
  master.key
  certificates/<证书标识>.json
  acme/
    accounts/<账户标识>.json
    plans/<证书标识>.json
    attempts/<任务标识>.json
    jobs/<任务标识>.json
```

- 新上传及自动签发证书使用独立 JSON 文件；证书私钥、ACME 账户密钥、DNS 凭据和订单恢复私钥均以 AES-256-GCM 加密保存。
- 文件权限 `0600`、数据目录 `0700`；密文通过 Base64 表示。原子替换前同步文件，替换后同步父目录。
- 任务 JSON 只包含域名、方式、环境和已脱敏状态，不含 DNS 凭据或私钥。任务 API 不提供秘密材料。
- 队列最多等待 16 项，自动证书配置最多 1000 项；保留每张证书的首次申请、最新任务及最近 200 项任务历史，界面最多返回最近 200 项。
- `master.key` 必须与加密材料一同备份；缺失时不能通过生成新密钥恢复已有材料。
- 网站配置、账户、证书与 ACME 材料已采用 JSON 文件；管理会话仅保存在内存，重启需重新登录。旧数据库手动证书通过离线转换保留，运行时不再读取数据库。转换及恢复流程见 [JSON 存储说明](json-storage.md)。

## 验证情况与使用前提

本次测试使用本机模拟 CA 和 DNS API，覆盖两种验证流程、通配符、续期热更新、失败清理、凭据保护、重复申请及已签发订单恢复，没有申请真实证书，也没有操作真实 DNS 区域。

实际申请还需要部署者提供域名及相应公网入口或 DNS 凭据。各服务商账户权限、区域限制、DNS 传播和 CA 限额需在实际环境验证；测试 CA 通过不代表真实账号权限已验证。

官方依据：[Let’s Encrypt 验证方式](https://letsencrypt.org/docs/challenge-types/)、[Cloudflare 令牌权限说明](https://go-acme.github.io/lego/dns/cloudflare/)、[腾讯云 DNS 适配说明](https://go-acme.github.io/lego/dns/tencentcloud/)。
