# v2way 卡片设计优化方案

- 日期：2026-11-04（Asia/Shanghai）。
- 状态：用户已授权实施，两阶段优化已完成；第 1–8 节保留方案基线，第 9 节记录实施与验证边界。
- 范围：站点管理、路由规则、后端服务、证书管理四类对象卡片；兼顾运行概览中的站点摘要。统计卡、ACME 申请面板、任务记录和系统设置面板只检查风格协调，不统一改造成对象卡片。

## 1. 检查依据与结论

本轮复核当前源码：`web/src/main.tsx`、`web/src/records.tsx`、`web/src/components.tsx`、`web/src/style.css` 和 `web/src/types.ts`，并参考已有布局优化记录。当前开发服务未运行，本轮未启动服务或重新进行浏览器量测；下文区分源码可确认的问题与实施时需要验证的视觉风险，不将历史截图当作本轮验收结果。

现有深灰背景、蓝色强调、细边框和紧凑信息布局适合继续沿用。建议保留布局基础，统一卡片内部结构，再优化各页面的信息与状态。

保持以下已确认规则：

- 主体内容最大宽度 1600px，居中显示。
- 网格按容器宽度自动排列，最小列宽 340px、单卡最大宽度 520px；窄屏缩至容器宽度，不恢复固定三列。
- 所有文字操作使用有背景、边框的标准按钮；删除等纯图标操作保留图标按钮。
- 站点未修改时显示原有启停状态；新增或发生修改时才显示“草稿”，发布或恢复原配置后移除标识。
- 保存草稿与发布仍为现有独立操作，不增加卡片点击即发布、隐式切换状态等行为。

## 2. 当前问题与优先级

| 编号 | 优先级 | 源码现状 | 优化方向 |
| --- | --- | --- | --- |
| C01 | P1 | 四类卡片共用外框，但站点使用标签与横向事实行，路由使用键值区，后端使用节点列表，证书使用域名标签与到期信息；信息顺序和密度差异明显 | 统一头部、核心信息、辅助信息、底部操作四个区域，正文按对象类型保留差异 |
| C02 | P1 | 网格已自动分列，头部换行仍由 720px、1100px 等视口断点决定 | 根据卡片自身宽度调整头部，避免宽屏内的小卡片继续按宽屏头部排列；需浏览器验证临界宽度 |
| C03 | P1 | 后端卡片用 `.every()` 汇总健康状态，空数组也会得到“可用”；同 ID 的草稿目标可能与已发布健康记录混合显示 | 区分未发布、暂无健康数据、全部正常、部分异常、全部异常；草稿新增节点不沿用旧节点健康状态 |

| C05 | P1 | 站点卡片域名最多预览三个，证书卡片直接展示全部域名；后端与路由的长文本处理也不同 | 统一预览数量、长文本展开方式和辅助操作位置，避免域名多的证书撑高整行 |
| C06 | P2 | 卡片按钮在桌面端被压到 29px，普通按钮通常为 34px；手机端虽已提升到 44px，视觉密度仍不一致 | 对象卡片普通操作统一为桌面 34px、手机 44px，图标按钮同步对齐 |
| C07 | P2 | 路由卡片的启停徽标实际表达所属站点状态，当前缺少上下文标签 | 明确写为“站点状态”，避免理解为路由自身有独立启停开关 |

| C09 | P2 | `.object-heading`、`.card-facts` 等样式分散多次定义，移动与桌面规则依赖覆盖顺序 | 合并共享规则，建立少量卡片专用变量与容器响应规则，减少后续局部改动互相影响 |

P1 优先解决理解、操作一致性和布局风险；P2 优化密度与维护成本。不因统一风格增加无业务价值的图表、装饰或统计数。

## 3. 统一结构与视觉规范

### 3.1 卡片骨架

推荐阅读顺序：

1. **头部**：对象图标、名称、对象副标题、一个主要状态。
2. **正文**：最常用的匹配条件、入口、目标或有效期。
3. **辅助区**：草稿说明、传输模式、健康摘要、续期设置等；详情按需展开。
4. **操作区**：常用按钮在左侧，删除图标靠右并与其他操作分开。

名称在同类卡片中使用相同字号。头部名称与状态冲突时优先允许状态换到下一行，不将名称挤成极窄列。卡片整体不设置点击事件，避免与展开、复制、编辑和删除按钮冲突。

不强制所有卡片同高度；保持同一行的底部操作对齐，不用空白占位模拟不存在的操作。展开详情可以增加卡片高度，但不改变网格列数或将整个卡片变为固定高度的滚动容器。

### 3.2 尺寸与层级建议

| 元素 | 建议 |
| --- | --- |
| 外框 | 保留深灰背景、1px 边框和 6px 圆角 |
| 内边距 | 桌面 20px，窄卡及手机 16px |
| 网格间距 | 保持约 16–18px，不增加大面积留白 |
| 标题 | 14px，适度提高字重，默认最多两行，保留标准展开按钮 |
| 核心值 | 13px；域名、路径、地址和数值可使用等宽字体 |
| 辅助标签 | 12px，控制低对比灰色使用范围，具体颜色需量测确认 |
| 键值区 | 标签约 64–72px，内容列可收缩并换行，顶部对齐 |
| 操作按钮 | 桌面至少 34px 高，手机至少 44px 高；间距 8px |
| 操作区分隔 | 保留细分隔线，上下间距保持一致 |

颜色承载明确含义：蓝色用于强调与选择，绿色用于已确认正常状态，黄色用于待处理或异常提醒，红色用于错误和危险操作。草稿状态不能仅凭绿色让用户误认为已经运行。

### 3.3 根据卡片宽度响应

保留现有网格及宽度上限，建议在卡片内部引入容器查询：

- 卡片内部宽度充足：图标、名称、主要状态同行。
- 卡片较窄：名称区占主要宽度，状态移至第二行；事实信息自然换行。
- 临界宽度建议先以约 380px 试排，再按真实内容调整，不将该值直接视为最终验收标准。
- 操作按钮可换行，删除按钮仍保留独立位置；按钮文字不截成省略号。

必须覆盖“屏幕很宽但每张卡片很窄”的场景，而不是只检查手机断点。

## 4. 各页面调整建议

### 4.1 站点管理

**头部**：站点名称、主域名、站点状态。

**正文**：

- 入口采用清晰的协议与端口信息，例如 `HTTP :8080`、`HTTPS :8443`；未配置入口时显示明确提示。
- 域名默认展示主域名及最多两个附加域名，剩余项通过“查看其余 N 个域名”标准按钮展开，提供复制功能。
- 路由数量保持可见；请求体上限放在辅助层，不与业务入口争夺相同视觉权重。

**状态**：继续逐站点比较当前配置与已发布版本。无变更显示“启用／停用”；有变更显示“草稿：启用／停用”，采用更中性的待发布视觉。草稿不能被描述为“离线”“运行失败”。

**底部**：保留“站点配置”“路由规则”和删除图标。两种常用操作使用相同按钮规格，删除保留现有确认流程。

### 4.2 路由规则

**头部**：名称、所属站点内的规则序号、动作类型。匹配方式放入正文或副标题，避免和状态徽标重复竞争头部空间。

**正文**：统一顺序为所属站点、匹配方式与路径、HTTP 方法、目标。目标标签按动作分别为后端池、静态目录、响应状态和跳转地址。

**辅助区**：

- 显式标注“站点状态”，沿用站点状态计算，不新增路由独立开关。
- 保留标准 HTTP／流式连接信息。
- 普通代理可显示“处理上限 60 秒”等有效值；存在自定义阶段超时时显示“自定义超时”，通过标准按钮展开连接、握手、响应头的有效值。
- 流式模式显示“不限制总时长”，同时说明阶段超时仍生效；不能把配置中的 0 展示成“无限”。

**底部**：保留“编辑规则”和删除图标。规则序号只能用于辅助定位，不能暗示执行优先级；实际匹配仍由精确匹配与前缀规则决定。

### 4.3 后端服务

**头部**：后端池名称、调度方式、节点总数和健康摘要。

**正文**：最多预览三个节点；每行将地址与“健康状态／权重”分为可换行的两层，避免长地址与右侧状态互相挤压。其余节点使用标准按钮展开，预览和展开列表采用相同信息结构。

**状态处理**：

| 条件 | 展示 |
| --- | --- |
| 尚无对应已发布后端池 | 未发布 |
| 已发布但没有可用健康记录 | 暂无健康数据 |
| 对应已发布节点均正常 | 全部正常，或 N/N 正常 |
| 部分已发布节点异常 | 部分异常，或 N/M 正常 |
| 全部已发布节点异常 | 全部异常 |
| 草稿新节点未出现在运行版本中 | 该节点标记“待发布”，不显示为健康或异常 |

是否已发布应比较运行版本对象，而不是仅以 `overview.health` 是否存在判断。空数组不能直接通过 `.every()` 得到“可用”。

健康摘要只针对当前真实运行对象。草稿配置与运行目标不一致时需要明确区分，不能将旧运行对象的健康值当作草稿健康值。探测路径继续为辅助信息，不将被动检测包装成主动探测已配置。

**底部**：保留“编辑后端池”和删除图标，不新增当前没有接口支持的单节点启停操作。

### 4.4 证书管理

**头部**：证书名称、来源及测试／正式环境、有效期状态。测试证书的信任限制应保持可见，不能因时间有效而仅显示绿色正常。

**正文**：

- 域名采用与站点卡片一致的预览数量和展开规则，不默认铺开全部 SAN。
- 到期时间与剩余时间集中展示；不足 24 小时时可显示“剩余 N 小时”，避免“1 天后到期”掩盖紧迫程度。
- 自动续期信息属于状态／辅助区，不与操作按钮混排。

**底部**：所有证书均有统一的指纹查看入口，使用标准按钮展开详情。ACME 证书增加现有“立即续期”按钮；手动证书不显示不可执行的续期按钮。

若需要展示签发中／续期中并禁用重复提交，应复用现有任务接口并向卡片提供任务摘要；当前任务状态主要保存在 ACME 面板中，该项需要调整共享状态，列为第二阶段。前端按钮禁用不能替代后端的并发签发保护。

不在本方案中新增证书删除、在线修改凭据或证书内容编辑。若未来需要“尚未生效”状态，应先确认前端能获得 notBefore 等必要字段，不能仅靠当前到期字段推断。

## 5. 长内容、详情与交互

- 标题、路径、目标地址使用相同的长文本组件；展开／收起继续为标准按钮，位置和间距统一。
- 核心内容不能仅藏在 hover 提示中，手机与键盘用户均应能查看完整值。
- 域名和节点详情使用同一套标准展开按钮，关联 `aria-expanded` 和 `aria-controls`；图标删除与复制保持可访问名称。
- 已有自定义确认弹窗与错误反馈继续复用，不恢复原生 alert/confirm。
- 编辑、查看路由、展开详情属于不同操作，不把整个卡片设计为一个大按钮。
- 复制等瞬时反馈不应撑开卡片高度或改变底部按钮位置。
- 正常与错误状态除了颜色还需文字表达；异常不能只显示一个红点。

## 6. 实施拆分

### 第一阶段：共享视觉与布局

1. 收敛卡片尺寸、文字和操作区样式，统一桌面与手机按钮尺寸。
2. 增加卡片内部容器响应规则，复核窄卡片的名称、状态与按钮排布。
3. 统一域名／目标折叠、长文本展开和详情入口。
4. 调整四类卡片的信息顺序、证书底部和路由站点状态标签。

建议抽取轻量的卡片壳、头部、键值信息与操作区组件；保留业务页面的数据与操作逻辑。避免创建大量只包一层 div 的组件，也不引入新的 UI 依赖。

### 第二阶段：状态与业务摘要

1. 修正后端池健康汇总与草稿／运行数据对应关系，增加空数据及节点变更回归。
2. 增加路由有效超时摘要，默认值与实际网关配置保持一致。
3. 优化证书剩余时间表达，并按现有任务接口提供签发／续期中状态。

第二阶段涉及数据语义与共享状态，应独立验证。不能将未实施的状态能力描述成第一阶段已完成的纯样式变化。

## 7. 验收标准

### 7.1 视觉与响应式

- 覆盖 320、390、768、1024、1440、1920、2560、3840px 视口，并补充一档短横屏。
- 四类对象卡片共用主体 1600px、单卡 520px 上限；列数随容器变化，无横向溢出。
- 覆盖一张卡片、满行、不满行、多行，以及长名称、超长路径、多个域名、多个节点。
- 验证窄卡片的状态不挤压名称，信息标签顶部对齐，展开后内容不遮挡底部操作。
- 手机按钮至少 44px，桌面常规操作按钮至少 34px；删除与常用操作保持可辨认间距。

### 7.2 状态与逻辑

- 站点未修改、新增、停用、修改后恢复、发布成功均显示正确状态。
- 路由卡片明确表达所属站点状态；显示的超时摘要遵循 0 使用默认值及流式豁免规则。
- 后端健康记录缺失、空数组、部分异常、全部异常、草稿新增／删除／改地址不产生误导。
- 证书手动／ACME、测试／正式、即将到期／过期、签发中／失败等状态在现有数据能力范围内正确呈现。

### 7.3 交互与验证边界

- 编辑、删除确认、页面跳转、复制、详情展开与搜索筛选均可用。
- 键盘焦点可见，展开状态与按钮标签正确，不因卡片结构变化破坏自定义弹窗。
- 浏览器回归使用模拟 API，不读取实际账号、修改开发配置、发布站点或触发真实签发。
- 样式调整不为自身添加实现镜像测试；状态汇总、默认值计算等行为变化才补充有价值的自动化测试。
- 按实际改动执行类型、测试与格式检查；只有获得明确授权才启动开发服务或执行构建。

## 8. 推荐顺序与待确认项

建议先实施第一阶段，再处理第二阶段。保持当前主题、主体宽度和自动列数，优先统一内部阅读顺序、按钮与窄卡片布局。

待实施时验证的参数：标题 14px 是否适合当前字体、容器换行阈值、域名与节点默认预览数量，以及证书极短剩余时间的表达方式。上述参数可在浏览器对照后微调，不能仅凭源码检查宣称最佳尺寸或可访问性已通过。


## 9. 实施记录（2026-11-04）

- 新增轻量共享卡片组件，统一头部、核心键值、三项域名预览、标准按钮详情及底部操作；保留1600px主体和520px单卡宽度上限。
- 卡片内部引入380px容器查询，独立于屏幕宽度调整状态位置；标题14px、核心值13px，操作按钮桌面34px、手机44px。
- 站点草稿状态采用黄色提示，保持逐站点差异规则；路由明确标注站点状态，并按有效值展示总预算及阶段超时。
- 后端健康按已发布节点匹配，空数组不再显示正常；区分缺失数据与异常，草稿新增目标显示待发布，摘要明确对应运行版本。
- 手动与ACME证书统一指纹入口；域名折叠和剩余小时提示已接入，测试证书保留不受浏览器信任说明；续期状态移入辅助区。
- 通过现有ACME任务接口共享状态，签发中、排队中及结果需检查时限制重复提交；增加请求期间锁定及旧轮询快照合并保护。
