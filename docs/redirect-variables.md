# 重定向请求变量

重定向路由可将原始请求的路径、查询串等信息拼接到跳转地址，无需配置后端服务。这里的变量来自本次请求，与 Header、固定响应共用变量列表，不读取操作系统环境变量。

## 使用方式

1. 在“路由规则”中新建或编辑规则，将动作设为“重定向”。
2. 开启“启用跳转变量”，填写目标模板。
3. 展开“可用变量与复制”，按需复制变量，选择 301、302、307 或 308。
4. 保留编辑、保存草稿，在发布预览中核对跳转变量开关和目标原文，然后发布。

开关默认关闭，旧规则和关闭模式继续使用固定跳转地址，不展开 `${...}` 或 `$$`。

## 常用示例

| 需求 | 跳转目标 |
| --- | --- |
| 更换域名，保留路径和全部查询参数 | `https://new.example.com${request_uri}` |
| 更换域名，仅保留路径 | `https://new.example.com${uri}` |
| 在本站增加路径前缀并保留参数 | `/new${uri}${is_args}${args}` |
| 切换到 HTTPS，保留原始 Host、路径及参数 | `https://${http_host}${request_uri}` |
| 固定查询参数与路径 | `https://new.example.com${uri}?source=v2way` |

`http_host` 包含原始端口；若源站 HTTP 使用 80 或自定义 HTTP 端口，切换 HTTPS 时通常应显式填写目标域名和 HTTPS 端口，避免沿用 HTTP 端口。

例如请求 `/docs/a%20b?x=1&x=2&q=%2B`，使用第一个模板会跳转到 `https://new.example.com/docs/a%20b?x=1&x=2&q=%2B`，保留参数顺序、重复参数和原始编码。

## 路径与查询变量

| 变量 | 含义 |
| --- | --- |
| `${uri}` | 原始转义路径，不带查询参数 |
| `${request_uri}` | 原始转义路径及查询部分，保留参数编码和顺序 |
| `${args}` | 原始查询串，不含问号，无参数时为空 |
| `${is_args}` | 请求带查询部分时为 `?`，否则为空；显式空查询 `/path?` 也保留问号 |

同时可使用 `${remote_addr}`、`${remote_port}`、`${scheme}`、`${host}`、`${http_host}`、`${request_method}`、`${request_id}`、`${site_id}`、`${route_id}`，详见 [完整变量列表](proxy-header-variables.md#可用变量)。新增的三个查询变量也可用于 Header 和固定响应正文。

`$$` 表示字面量美元符号；`$${uri}` 输出 `${uri}`。普通 `$name` 原样保留，展开结果不递归解析。

## 校验与边界

- JSON 配置沿用 `location`，可选 `locationVariables: true`；开关只用于重定向动作，切换其他动作时控制台清除。
- 模板按配置快照编译，每个请求独立展开；模板与展开后的目标最多 8192 字节。
- 保存编辑时校验变量名称与目标结构，发布时后端重新校验；草稿可暂存尚未完成的配置。
- 运行时再次校验最终 URL，仅接受本站绝对路径或不含用户信息的 HTTP/HTTPS 地址。拒绝 `//host` 协议相对地址、反斜杠和控制字符，不允许模板展开绕过这些限制。
- 缺失必需变量、超长结果或非法目标返回 400，不发送 `Location`，错误不回显模板或查询内容。
- 来源 IP 和协议来自实际连接，不信任转发头。路径变量遵循网关既有路径检查，不改变原有编码路径的准入规则。
- 变量按文本拼接，不自动做 URL 组件编码。`${uri}` 与 `${request_uri}` 已保留原始编码；`${args}` 适合放在查询部分，勿将用户可控查询串直接当作完整跳转目标。
- HEAD 返回相同的状态码和跳转头，不返回正文；状态码仍只支持 301、302、307、308。
