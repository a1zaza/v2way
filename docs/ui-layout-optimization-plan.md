# v2way 全页面与弹窗样式布局优化方案

> 检查日期：2026-11-02（Asia/Shanghai）
>
> 状态：用户已授权实施，主要优化已完成。第 1–9 节保留实施前的巡检与方案基线，第 10 节记录实施结果和验证边界。
>
> 基线：当前 React 控制台；沿用深灰背景、蓝色强调、紧凑布局及等宽信息展示，不重新设计品牌。名称始终使用小写 `v2way`。

## 1. 检查范围与方法

检查登录页、8 个管理页、加载/失败状态、移动导航、全局反馈，以及全部 10 类自定义弹窗。弹窗进一步检查条件字段、长内容、滚动到底部和错误状态。

| 范围 | 检查对象 |
| --- | --- |
| 页面 | 登录、运行概览、站点管理、路由规则、后端服务、证书管理、访问日志、配置版本、系统设置 |
| 编辑弹窗 | 站点配置、后端池配置、路由配置；路由覆盖代理、静态目录、固定响应、重定向和高级请求头 |
| 操作弹窗 | 预览并发布、通用操作确认、上传 TLS 证书、申请免费证书、导入 JSON、路由规则推演、请求详情 |
| 确认分支 | 删除站点、删除路由、删除后端池、回滚版本、放弃本地编辑 |
| ACME 分支 | HTTP-01；DNS-01 下 Cloudflare、腾讯云、阿里云、DigitalOcean、Linode、RFC 2136 的字段布局 |
| 边界状态 | 无数据、有数据、长名称/域名/路径/备注、多目标、多任务、导入失败、发布失败、待确认、加载失败 |
| 额外原生对话框 | 损坏草稿重建使用的 `window.confirm`，以及离开页面时浏览器自身的未保存提醒；不属于可直接用 CSS 调整的自定义弹窗 |

实际浏览器检查使用 Chromium，视口为 **1440×1000、1024×844、768×844、390×844、320×844**，每个视口覆盖 49 个页面/弹窗状态，共 **245 个组合**，另补查搜索无结果、未保存关闭、提交中和放弃编辑。

全部管理 API 在独立浏览器上下文中拦截并返回模拟数据；未读取开发密码、保存实际草稿、发布站点、修改密码或调用真实 CA。模拟数据含 5 个站点、4 个后端池、4 类路由、15 条日志、3 张证书、5 类签发状态和 2 个历史版本。它用于暴露布局边界，不代表开发实例的真实业务数据。

证据来自截图观察、DOM 尺寸量测和源代码复核。245 个组合未记录到页面 JavaScript 异常，也未发现整个文档或主内容容器的横向溢出；**这不等于各个表格都可读、所有操作都容易到达**。

本轮未验证 Safari/Firefox、真实手机软键盘、实际浏览器 200% 缩放和读屏软件，也没有执行生产构建。相关检查列入后续验收，不能视为已通过。

## 2. 主要结论与证据

当前视觉方向和基础响应式结构可以保留。优先修复移动端数据表格，再统一弹窗结构、文字可读性与反馈状态，最后处理卡片节奏和细节一致性。

优先级定义：**P0** 为核心信息或操作在常见视口下明显难用；**P1** 为影响理解、编辑或反馈的主要问题；**P2** 为一致性、密度和操作效率改进。

| 编号 | 优先级 | 已确认的问题/现状 | 证据与影响 |
| --- | --- | --- | --- |
| A01 | P0 | 小屏表格将长文本挤成逐字竖排 | 390px 视口中，4 条路由表格约 1793px 高，15 条日志表格约 6202px 高；日志首行约 1089px、请求列约 52px 宽，操作列还需横向滚动。不是单纯“容器未溢出”就可接受 |
| A02 | P1 | 重要辅助信息过小、偏暗 | 表头 10px、表格 11px、字段说明 10px。选定静态配色的亮度对比计算：字段说明约 3.84、表头约 3.59、表格辅助信息约 3.46；小字号下辨读吃力 |
| A03 | P1 | 长表单依赖整个弹窗滚动，内容与粘性头尾耦合 | 390px 下站点弹窗内容约 1467px、可见高度约 818px；RFC 2136 表单约 1275px。现有头尾已使用 sticky，应保留这一优点，但统一为明确的正文滚动区域 |
| A04 | P1 | 移动端触达面积不足 | 常见图标按钮为 30×30px，列表操作约 28–34px 高；开关本体为 30×18px。需要扩大可点击区域，不只是放大图标 |
| A05 | P1 | 提交中状态不完整，关闭与编辑状态不直观 | 模拟 ACME 提交中，7 个输入控件均未禁用、关闭图标仍启用，未设置 `aria-busy`；提交/取消虽禁用，但表单整体状态不一致 |
| A06 | P1 | 发布失败与成功提示同时存在 | 模拟端口占用后，弹窗上方红色错误与绿色“配置与资源校验通过”同时显示；背景还出现重复的全局错误 |
| A07 | P1 | 复杂编辑表单层级不足 | 站点监听、证书、策略连成长表单；路由四类动作与高级请求头共用一个编辑区域；小屏后端目标仍按地址/权重/删除三列排列 |
| A08 | P1 | 部分搜索无结果状态缺失 | 访问日志过滤后可出现“0 行、0 个空态提示”，计数仍显示全部记录数。路由/后端有相似的条件渲染结构，需统一处理 |
| A09 | P1 | 弹窗关闭和焦点管理仍需统一 | 已有 Escape、Tab 循环和关闭后焦点恢复；但编辑后按 Escape 会直接关闭并丢弃未保留输入，背景区域没有统一 inert 控制 |
| A10 | P2 | 卡片内容高度与操作基线不一致 | 多域名、长名称、多目标让部分卡片明显增高，按钮位置随正文长度变化，浏览节奏不稳定 |
| A11 | P2 | 详情与技术文本缺少分层展示 | 长路径、请求标识、指纹和完整 JSON 占用大量空间；当前主要依赖换行或嵌套滚动，缺少完整值查看/复制的一致入口 |
| A12 | P1 | 加载与恢复页面缺少独立版式 | `.boot` 将图标、长错误文字、重试及恢复操作放在同一个居中 flex 容器中；需要适应错误长度和操作数量变化 |

配色数字是对源代码中选定前景/背景色的静态计算，不是完整无障碍认证结论。后续采用正文/关键说明对比值不低于 4.5 的产品目标，仍需在浏览器和不同状态下复核。

## 3. 统一布局规范

### 3.1 页面框架

- 保留侧栏、顶部工作区和底部状态栏，不新增装饰性面板。
- 页面统一为“标题与主操作 → 筛选/摘要 → 内容 → 分页或结果说明”。搜索、筛选与计数使用同一行距规则。
- 桌面页边距建议 24–32px，移动端 16px；模块间距 20–24px，卡片内部 16–20px。使用 4/8px 间距基准，减少孤立数值。
- 页面标题桌面 24px、手机 22px；正文/输入桌面 13px、手机 14px；标签和有效说明 12px。不再用 9–10px 承载端口、路径、状态、时间等任务必需信息。
- 页面标题主操作只保留当前页面最重要的动作；顶部“预览并发布”作为工作区操作保持可见，但与页面动作在视觉层级上区分。
- 系统设置与普通长表单左对齐，建议最大阅读宽度 1040px；概览和数据列表继续使用可用内容宽度。

### 3.2 响应式行为

| 可用视口 | 页面和表格 | 弹窗和表单 |
| --- | --- | --- |
| ≥1200px | 概览双栏、对象双栏；表格保留主要列 | 标准/宽型弹窗；短字段可双列 |
| 721–1199px | 依据内容容器宽度收敛卡片，不仅依赖全屏宽度 | 表单可双列，但地址等长输入保持整行 |
| ≤720px | 对象单栏；日志/路由采用移动记录视图；筛选分行 | 弹窗接近全屏、正文独立滚动；普通字段单列 |
| 320px 边界 | 操作不可挤出屏幕，长技术文本不逐字占满整列 | 长标题可自然换行；关闭按钮不能被挤小；页脚保留所有关键动作 |

数据表格的短期修复是明确列宽与最小表宽，提供局部横向滚动及可见提示，停止压缩成逐字竖排。最终移动视图建议使用记录卡片：路由显示路径/动作/站点/编辑，日志显示状态/方法/路径摘要/时间/详情；完整字段进入详情，不通过无限加高行来展示。

### 3.3 文字、状态与长内容

- 普通名称最多两行；域名、地址、路径保留等宽展示，列表中可截断，但必须提供可访问的完整值查看方式。
- 关键长值提供复制；成功后只显示轻量反馈，不反复弹全局通知。触屏不能只依靠 hover 提示获取完整信息。
- 区分“当前运行”“草稿已保存”“本地未保存”“待发布”，统一命名和颜色，避免将草稿中的启用标记当作已经生效。
- 正常状态蓝/绿，异常与危险动作使用明确文字加颜色；不能仅靠灰色圆点表达健康异常。
- 搜索结果计数采用“匹配数 / 总数”。无结果显示原因、清除搜索/筛选入口，不留下只有表头的区域。

### 3.4 所有自定义弹窗的结构

统一为 `标题区 / 正文滚动区 / 操作区` 三部分。标题和操作区不参与正文滚动，不因内容长度互相覆盖；表单的语义结构和提交行为保持完整。

| 类型 | 建议桌面宽度 | 适用内容 |
| --- | --- | --- |
| 确认型 | 420–480px | 删除、回滚、放弃编辑 |
| 标准型 | 560px 左右 | 路由推演、上传证书、请求详情 |
| 表单型 | 720px 左右 | 站点、后端池、路由、ACME |
| 预览型 | 960px 上限，并受视口限制 | 配置差异、JSON 导入预览 |

- 不能只靠扩大宽度修复内容组织问题；手机统一单列，宽度为视口减两侧安全间距。
- 短确认弹窗按内容自然高度，不强行全屏；长编辑弹窗在手机上使用可用动态视口高度，并保留安全区。
- 标题、副说明、关闭按钮采用相同边距和对齐规则；长标题允许两行，关闭按钮保持独立尺寸。
- 页脚明确区分“保留本地编辑”“导入草稿”“发布生效”；不把所有按钮都命名为“确认操作”。
- 提交中禁用会造成重复或误解的操作，提交按钮显示动作与进度；若不能关闭，应同步禁用关闭按钮并给出原因，不能只让点击失效。
- 编辑弹窗有未保留输入时，关闭/Escape 进入统一的放弃确认；敏感凭据不持久化到浏览器存储。
- 保留现有焦点循环和焦点恢复，补齐背景 inert、标题/说明关联、字段错误关联；无障碍说明不需要暴露内部实现细节。
- 关键字段错误在字段旁显示，顶部仅给出摘要；提交失败滚动/聚焦到错误区域，保留用户输入。

## 4. 逐页面改进

| 页面 | 确认现状与问题 | 建议调整 | 优先级与验收 |
| --- | --- | --- | --- |
| 登录 | 手机品牌区与表单之间留白较大；提示偏暗；失败会改变表单高度 | 保留简洁单栏，控制品牌与表单间距；输入与主按钮对齐；错误放在字段后统一位置；初始化帮助作为次级说明 | P1：320px 下表单、错误和登录按钮可到达，输入聚焦不被软键盘遮住 |
| 运行概览 | 横幅、指标、站点与活动结构完整；长域名/活动和大数字会竞争空间；多个建站入口重复 | 收敛横幅高度；保留一个明确建站引导；数字使用等宽数字并限制换行；站点摘要显示草稿属性，运行信息明确来源 | P2：长名称和八位数字不挤压状态/操作；空态与有数据态结构一致 |
| 站点管理 | 卡片已有端口信息；多域名卡与普通卡操作基线不同，端口信息过小 | 标题最多两行；域名默认展示少量并显示余量；HTTP/HTTPS 端口各有清晰标签；底部操作对齐，危险动作降低误触 | P1/P2：手机能直接识别启用协议及端口；长域名不挤压编辑按钮 |
| 路由规则 | 小屏表格逐字竖排；目标摘要可能优先读取残留的后端引用，与实际动作不一致；筛选无结果提示不足 | 优先修复移动记录布局；桌面分配路径/目标足够宽度；目标摘要按代理/静态/响应/跳转分别生成；筛选数量与空态统一 | P0：长路由在手机一条记录内可读，编辑/删除直接可达；动作摘要与真实动作一致 |
| 后端服务 | 多目标全部展开使卡片很高；“存在异常”可落入灰色徽标；长 URL 竞争权重列 | 显示前三个目标与展开入口；地址/权重/健康分栏；异常使用明确警告样式；保持卡片操作基线 | P1：能区分未发布与健康异常；多目标不撑坏卡片和小屏 |
| 证书管理 | ACME 面板和展开任务位于证书前，任务多时挤占主要内容；页面与任务区存在多层滚动 | 证书与签发任务建立明确分区；任务先给状态摘要，展开后查看列表；到期、测试证书、续期状态分别展示；指纹折叠并可复制 | P1：首屏可找到证书与申请动作；异常任务可见但不吞没证书列表 |
| 访问日志 | 小屏路径/站点逐字换行，15 条记录约 6202px；详情入口位于末列；搜索可留下空表体 | 手机改为紧凑记录；桌面路径摘要限高，完整路径进入详情；筛选计数一致；说明当前展示上限，后续分批展示 | P0：详情入口无需横向寻找；单条摘要通常不超过 3–4 行，完整值可查看 |
| 配置版本 | 长备注推高记录，时间偏小；发布摘要和全局按钮重复；回滚禁用原因不明显 | 固定版本/状态/时间层级；备注两行后展开；工作区摘要中区分保存与发布；禁用回滚时说明原因 | P1：长备注不挤出回滚按钮；当前版本明确，回滚风险在确认框中可见 |
| 系统设置 | 已删除存储介绍卡片；监听信息正确按实际列表显示；多站点名称与地址仍会拉长同一值区 | 保留实例信息、导入导出、账户安全三块；每个监听用协议/地址/共享站点分行，站点列表适度折叠；密码表单与区块操作对齐；异常才显示恢复提示 | P2：不恢复存储技术介绍卡；无监听、单监听、多站点共享均清晰 |
| 加载/恢复 | 加载、长错误和多操作共用单行居中布局 | 改为有最大宽度的状态区域：图标、标题、原因、建议、操作依次排列；恢复动作与普通重试分层 | P1：320px 下长错误不挤出按钮；用户能区分等待、重试和恢复 |

其中“目标摘要按动作生成”“匹配数/总数”属于为正确展示信息所需的小范围逻辑调整，应与样式变更一起评审，不能通过纯 CSS 掩盖。

## 5. 逐弹窗改进

| 弹窗 | 现状与重点问题 | 改进方案 | 优先级 |
| --- | --- | --- | --- |
| 站点配置 | 基本信息、HTTP/HTTPS、证书、跳转、限额和 CIDR 连成长表单；启用 HTTPS 后高度继续增加 | 分为“基本信息 / 监听与证书 / 访问策略”，可折叠非必填策略；HTTP 与 HTTPS 字段分组，明确留空与开关关系；端口不预填；拒绝未知 SNI 的说明保持可读 | P1 |
| 后端池配置 | 五个目标使表单超过可见区域；手机仍为地址、权重、删除三列，URL 可视范围窄 | 每个目标作为一组，手机地址独占整行，第二行为权重和删除；增加目标有稳定位置；多目标显示序号和数量；删除按钮与当前组绑定 | P1 |
| 路由配置 | 四种动作字段和通用策略混在同一滚动流；高级请求头产生长 JSON 编辑区 | 基本匹配、目标动作、传输、高级策略分区；动作切换时只展示相关字段并清楚标注；长地址整行、短状态/超时可并列；高级 JSON 区有说明与定位错误 | P1 |
| 预览并发布 | 680px 中并排两份完整 JSON 太窄；展开后产生嵌套滚动；失败与绿色成功提示冲突 | 使用预览型宽度；先展示对象与端口/协议/证书变更摘要，原始 JSON 次级展开；手机按“当前/即将发布”切换或顺序展示；区分预检完成、发布中、发布失败、结果待确认 | P1 |
| 通用操作确认 | 删除/回滚/放弃均使用蓝色“确认操作”；对象名称藏在正文中；缺少操作特定的反馈结构 | 标题、对象、影响、主动作分层；删除按钮明确为“删除站点/路由/后端池”，回滚按钮明确为“回滚并发布”，放弃按钮明确为“放弃编辑”；颜色随动作风险变化 | P1 |

## 6. 特殊状态与公共覆盖层

- **移动导航**：作为独立覆盖层处理焦点进入/返回、Escape 关闭与背景隔离；不要与表单弹窗同时争抢焦点。
- **全局错误**：页面级错误放页面，弹窗操作错误放当前弹窗；同一错误不重复显示在背景顶栏与弹窗内。
- **待确认状态**：保留现有确认入口，简短说明暂停写入的原因；不重新增加常驻存储介绍卡片。
- **成功反馈**：保存本地、保存草稿、提交签发、发布生效使用不同文案；只把重要反馈放全局 toast。
- **加载/禁用**：按钮、字段、关闭入口、进度文案使用一致规则；disabled 不仅降低透明度，也需要解释关键禁用原因。
- **帮助和字段错误**：`Field` 支持说明关联与错误关联；错误不能仅出现在弹窗最底部。原有标签关联、键盘焦点和 Escape 行为必须回归。
- **长内容**：输入框可以内部滚动，列表摘要可以截断，详情必须保留完整值；不要对所有文本全局设置 `word-break: break-all`。
