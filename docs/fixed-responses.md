# 固定响应与正文变量

固定响应路由直接返回文本，无需后端服务。可用于健康检查、来源 IP 查询或简单的诊断信息。

## 配置方法

1. 在“路由规则”中新建或编辑规则，选择所属站点、匹配路径与方法。
2. 将“动作类型”设为“固定响应”，填写响应状态码和纯文本响应内容。
3. 需要请求变量时开启“启用正文变量”，从“可用变量与复制”中复制变量。
4. 保留编辑、保存草稿并预览发布；发布后生效。

默认状态码为 200，响应类型为 `text/plain; charset=utf-8`。关闭正文变量时原样返回输入，包括 `${...}` 和 `$$`；旧配置保持此行为。

## 示例

只返回来源 IP，正文填写：

```text
${remote_addr}
```

混合固定文本与变量，支持多行：

```text
来源 IP：${remote_addr}
请求路径：${uri}
请求标识：${request_id}
```

变量与 [Header 变量](proxy-header-variables.md) 共用相同名称和语义：

| 变量 | 含义 |
| --- | --- |
| `${remote_addr}` | 实际连接来源 IP，规范化 IPv4-mapped IPv6，不信任转发头 |
| `${remote_port}` | 实际连接源端口 |
| `${scheme}` | 客户端到网关的 http 或 https |
| `${host}` | 规范化域名或 IP，不带端口 |
| `${http_host}` | 原始 Host，保留端口 |
| `${request_method}` | 请求方法 |
| `${uri}` | 原始转义路径，不包含查询参数 |
| `${request_uri}` | 原始转义路径及查询部分 |
| `${args}` | 原始查询串，不含问号，无参数时为空 |
| `${is_args}` | 请求带查询部分时为问号，否则为空 |
| `${request_id}` | 与本次访问日志一致的请求标识 |
| `${site_id}` | 匹配站点 ID |
| `${route_id}` | 匹配路由 ID |

`$$` 返回字面量 `$`，例如 `$${remote_addr}` 返回 `${remote_addr}`。普通 `$name` 按原文保留；变量展开结果不会再次作为模板解析。变量按文本插入，不做 JSON、HTML 或 URL 编码。

## 校验与运行行为

- 正文变量仅支持固定响应路由，与代理的 Header 变量开关相互独立；切换其他动作时控制台清除正文变量开关。
- 开启时，模板及展开结果均最多 65536 字节（64 KiB），按 UTF-8 字节计数，支持换行；不改变 Header 原有 8192 字节及禁止换行的限制。
- 未知变量、空变量、缺少结束括号或模板超长不能发布；错误提示不回显模板内容。草稿可暂存未完成配置。
- 运行时变量不可用或展开结果超限时返回 400，不输出部分正文。
- HEAD 不返回正文；204 不允许配置非空正文；304 不返回正文。状态码仍沿用固定响应的 200–599 范围。
- 站点访问策略、维护状态、IP 授权和请求限制仍先于业务响应生效，访问日志记录实际写出的下行正文体积。

JSON 配置沿用 `action: "response"` 和 `body`，新增可选 `bodyVariables: true`，缺失或 false 时不解析变量。发布预览展示原始正文和开关变化，不提前替换为管理员当前请求信息。
