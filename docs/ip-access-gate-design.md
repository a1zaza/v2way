修订：授权有效期为 48 小时滑动续期；部署方式已确认为客户端直连网关，仅使用 `RemoteAddr` 识别来源 IP，不设计 CDN 或前置反向代理接入。

## 1. 功能目标与默认选择

提供一个不出现在公开导航中的访问登录页面。用户成功登录后，网关记录其来源 IP；只有已授权 IP 才能访问标记为受保护的站点。

一次登录授权一组站点：所有开启“需要 IP 登录授权”的站点共用一个动态白名单。未标记站点保持原有访问方式。该功能是站点业务登录之前的一层入口控制，不替代应用自身账号和权限。

| 项目 | 第一版建议 |
| --- | --- |
| 站点标记 | “需要 IP 登录授权”开关，默认关闭 |
| 登录入口 | 指定一个已发布站点及其精确域名，在该站点的 HTTPS 入口提供随机隐藏路径 |
| 登录凭据 | 独立的访问账号，不复用控制台管理员账号；第一版一个账号 |
| 授权范围 | 当前网关内所有已标记站点，共享 IP 集合 |
| 授权有效期 | 登录后有效 48 小时；有效期内正常业务访问后，续期至本次访问时间 +48 小时 |
| 未授权响应 | 统一 404，不自动跳转登录页，不暴露入口地址 |
| 授权存储 | 独立 JSON 文件，内存索引查询，重启保留未过期授权 |
| 配置生效 | 入口与站点标记沿用保存草稿、校验、发布流程 |
| 撤销授权 | 管理端撤销单条或清空，持久化成功后立即影响新请求 |

48 小时滑动续期为已确认要求；客户端直连并仅使用 `RemoteAddr` 也为已确认要求；独立账号、共享授权范围与拒绝响应仍为本版建议，实施前可调整。

## 2. 用户操作与页面设计

### 2.1 控制台：系统设置 → 访问授权

新增一个紧凑设置分区，不增加工作空间或独立租户概念：

1. 配置独立访问用户名和密码。密码沿用本项目至少 8 个字符、最多 1024 字节的规则，使用现有 Argon2id 参数；不默认填入 admin，不自动复用管理员密码。
2. 选择登录入口站点和精确域名。该域名必须属于该站点，站点必须启用 HTTPS 并具备有效证书；不新建全局端口或新的启动参数。
3. 生成隐藏路径，例如 `/__access/<随机值>`。默认使用 32 字节密码学随机数的 64 位十六进制编码；提供复制完整地址、重新生成按钮，不提供容易与业务路由混淆的自由路径输入。
4. 展示只读授权策略：“正常访问后自动续期 48 小时；连续 48 小时无正常访问需重新登录”。第一版不提供固定有效期或永久授权选项。
5. 查看已授权 IP：IP、授权时间、最近正常访问、预计到期时间、来源账号、状态；支持搜索、撤销、清空，不展示密码摘要或登录令牌。

入口地址属于草稿配置。访问账号修改、自动续期、IP 撤销属于安全运行操作，不等待业务发布；敏感管理操作单独确认。凭据修改和清空白名单使用自定义确认弹窗；清空操作明确显示会影响多少个 IP。

### 2.2 控制台：站点配置 → 访问策略

新增“需要 IP 登录授权”开关，说明：

> 开启后，仅允许通过隐藏登录页授权且未过期的 IP 访问。与现有 IP 白名单、黑名单同时生效，保存草稿并发布后应用。

站点卡片仅展示运行状态及 IP 授权开启状态，不提供关闭/恢复站点或切换 IP 授权的独立按钮。修改统一通过站点配置弹窗进行，沿用本地编辑、保存草稿与发布流程。

卡片信息区在开启时显示简短“IP 授权”标记，与启用、维护中等站点运行状态分开；不在每张卡片重复放置隐藏登录地址。路由卡片保持现有布局，不增加站点状态。

发布影响摘要列出站点保护的开启/关闭，以及入口站点、域名、隐藏路径的变化。自动续期不修改站点草稿，不产生业务配置版本。

### 2.3 隐藏登录页面

独立中文深色页面，沿用 v2way 字体和表单样式，仅包含：

- 用户名、密码、登录按钮；不预填用户名。
- 网关从 `RemoteAddr` 识别的当前来源 IP，帮助确认网络变化。
- 表单内错误提示；用户名不存在与密码错误使用同一提示。
- 登录成功后的“当前 IP 已授权”、实际 IP、预计到期时间，以及正常访问会自动续期的说明。
- “撤销当前 IP 授权”按钮，明确同一出口 IP 下的设备会一并失去授权。

不显示控制台入口、站点列表或外部资源。成功后停留在结果页，用户自行访问已知站点；第一版不接受任意 returnUrl，避免入口泄露和开放重定向。

“隐藏”仅表示不在公开页面链接、不被索引、不自动跳转暴露。真正的访问控制依赖密码验证、IP 记录与有效期，不能依靠路径保密。

## 3. 请求流程与优先级

```text
业务请求
  → HTTP-01 挑战专用处理（沿用现状）
  → 端口、域名、TLS/SNI 与路径合法性校验
  → 从 RemoteAddr 提取并规范化来源 IP
  → 现有静态 IP 黑名单 / 白名单
  → 维护状态：返回 503
  → 站点请求限额
  → 若为绑定入口的隐藏登录路径：进入访问认证处理
  → 若站点要求 IP 登录：校验动态 IP 授权
  → HTTPS 跳转、精确路径 / 最长前缀匹配及业务动作
```

控制规则：

1. 现有黑名单优先；配置静态白名单时，访问者仍须满足静态白名单。动态登录授权是附加条件，不覆盖黑名单，也不以 OR 方式绕过静态策略。
2. 登录页面只豁免动态 IP 授权检查，仍受来源校验、静态 IP 策略、维护状态和独立登录限流约束。入口站点本身可开启 IP 登录保护，不发生递归拦截。
3. 登录路径精确绑定入口站点、精确域名、HTTPS 端口和隐藏路径；其他域名、端口不得处理该入口，不落入代理或静态目录。保留整个 `/__access/` 命名空间，配置冲突时校验拒绝，而不是由列表顺序决定。
4. 未授权 IP 的代理、静态文件、固定响应、重定向、WebSocket 握手和 SSE 新连接统一返回 404；HEAD 保持无正文，显式请求 JSON 时沿用错误 JSON 格式。不发送登录地址或 WWW-Authenticate。
5. 正常授权后继续执行既有路由、请求限制与应用认证，符合下述条件时更新滑动有效期。隐藏登录和拒绝请求不计入后端池业务统计。
6. 未知 HTTPS 域名仍在握手阶段拒绝，不为了展示 404 或登录页面提供兜底证书。维护中站点仍返回维护页，IP 授权不能解除维护。

## 4. IP 识别与放行边界

### 4.1 统一来源解析

仅使用 TCP 连接的 `RemoteAddr`（对应 remote_addr），通过 `netip` 规范化：去除端口、IPv4-mapped IPv6 转为 IPv4；不接受客户端提交“需要加入白名单的 IP”。授权记录仅存单个 IPv4 或 IPv6 地址，不自动扩展网段。

登录、动态授权检查、静态 IP 策略及相关审计必须使用同一来源解析器，避免登录按一种 IP 写入、业务访问按另一种 IP 查询。

已确认客户端直接连接网关，不增加可信代理模式、代理网段配置或转发链解析。`X-Forwarded-For`、`X-Real-IP`、`Forwarded`、`CF-Connecting-IP` 等头均不得用于登录 IP、授权查询、续期或撤销。无法解析 `RemoteAddr` 时拒绝授权，不回退读取请求头。

### 4.2 本功能固有语义

- 同一公网出口/NAT 下多个用户共享一个 IP，一人授权后该出口下其他设备也会放行；这不是按设备或按人的访问会话。
- IP 改变需要重新登录。IPv4 与 IPv6 分别授权，不推断两者属于同一用户；入口域名和目标域名走不同 IP 协议时也需分别授权。
- 白名单是“全局已授权 IP 集合”，标记为受保护的新站点也会接受尚未过期的已有 IP。按站点分组或按账号授权站点留到后续，不暗含在第一版中。
- 授权到期、撤销和清空对后续请求立即生效；已经开始的普通响应、SSE 与 WebSocket 不主动中断，沿用现有连接生命周期。若后续要求即时断连，再增加连接登记与回收能力。
- 登录页面与受保护内容使用 `Cache-Control: private, no-store`，覆盖代理、静态、重定向及错误响应，不允许路由头覆盖，避免浏览器直接复用缓存而跳过新的授权检查。此设置不主动删除客户端已有内容。

### 4.3 48 小时自动续期规则

有效期按连续 48 小时计算，不按自然日或零点计算。首次登录成功时，`expiresAt = grantedAt + 48 小时`。有效期内的正常业务活动更新 `lastAccessAt`，并令 `expiresAt = lastAccessAt + 48 小时`；同 IP 在任意已标记站点的活动均可续期，全局共用到期时间。

“正常访问”在第一版中的判定：

- 请求通过静态及动态访问控制、限流检查，匹配受保护站点的业务路由，实际响应为 2xx 或 3xx；包括静态文件、304、代理成功响应及业务重定向。网关仅用于升级 HTTPS 的跳转不计入。
- WebSocket 成功升级的 101 响应计入。成功建立的 SSE / WebSocket 在有效期内实际传输业务连接数据时也可续期，不必等到连接结束；同一数据块不重复刷新，后台可以合并活动时间更新。
- 登录页面 GET、查看授权状态、健康探测、ACME 挑战、未标记站点访问、未匹配路径、被拒绝请求、4xx/5xx 或未成功建立连接的请求不续期。应用返回 401/403 时，用户须通过正常成功请求或重新进行访问授权登录维持授权。
- 续期必须在执行时再次确认记录仍存在、账号修订一致且当前时间严格早于到期时间。已过期、已撤销、已清空或已改密的记录不得被慢请求或旧长连接重新激活。

连续 48 小时没有正常业务活动后授权失效，需要重新登录，不设置额外宽限期。若在到期边界同时收到请求，先检查授权，`当前时间 >= expiresAt` 即拒绝，不允许先续期再判断。

示例：11 月 5 日 09:00 登录，最初到期为 11 月 7 日 09:00；11 月 6 日 18:00 正常访问后变为 11 月 8 日 18:00；11 月 8 日 17:30 再次正常访问后变为 11 月 10 日 17:30。若此后没有正常访问，11 月 10 日 17:30 起需重新登录。

## 5. 数据模型与 JSON 持久化

### 5.1 版本化业务配置

| 位置 | 字段 | 含义 |
| --- | --- | --- |
| `Config.accessGate` | `enabled` | 是否配置并开放访问登录能力，默认 false |
| 同上 | `entrySiteId` | 登录入口站点 ID |
| 同上 | `entryDomain` | 入口站点绑定的精确域名 |
| 同上 | `loginPath` | 固定前缀与随机值生成的完整路径 |
| `Site` | `requireIpLogin` | 是否要求动态 IP 登录授权，默认 false |

配置随草稿、运行文件及历史版本保存。旧 JSON 缺少字段时保持原有行为。导出可包含入口配置，但不包含账号摘要或已授权 IP；隐藏路径因此不作为认证密钥。

### 5.2 私有授权状态

建议新增 `.data/access-control.json`，权限 0600；复用数据目录实例锁及 JSON 原子写入方式，不使用 SQLite。一个文件保存访问账号与授权集合，便于改密并清空授权在同一次持久化中完成：

| 内容 | 字段示意 |
| --- | --- |
| 文件元数据 | `schemaVersion`、`revision` |
| 独立账号 | `username`、`passwordHash`、`accountRevision`、`enabled` |
| 授权记录 | `id`、`ip`、`username`、`accountRevision`、`grantedAt`、`lastAccessAt`、`expiresAt` |

账号改名、改密或禁用时，递增账号修订并清空已有授权；登录并发写入必须重新核对账号修订。业务配置回滚不回滚访问账号或白名单，不能恢复已撤销的授权。

请求检查使用有界内存 map；默认最多 4096 个有效 IP。过期记录按时间判断立即失效，后台定期清理；容量满时先清理过期记录，仍满则拒绝新增并提示管理端，不自动扩大权限。

请求授权检查只读内存；正常访问续期时更新内存中的 `lastAccessAt`、`expiresAt` 并标记待落盘。自动续期每 60 秒合并持久化一次，避免每次资源请求或流式数据传输都重写整个 JSON；正常退出时等待写入并保存最终活动快照。登录、重新授权、撤销、清空、账号更新则串行同步写入，成功落盘后发布新的内存快照并返回成功。重新登录同 IP 更新授权与到期时间，不新增重复记录。

异常退出时，重启只恢复最后成功落盘的续期时间，可能丢失最多一个正常刷盘周期的活动；不使用重启时间补足 48 小时。60 秒刷盘周期属于落盘策略建议，若要求异常退出也精确保留每一次续期，则实施时须改为同步提交或增加持久化活动日志，不能宣称定期刷盘具备逐次续期的崩溃一致性。

落盘任务与撤销/清空/改密共用写锁，写入前按当前记录 ID 与账号修订核对合并，不把先前排队的活动快照覆盖回最新授权集合。只调整活动时间的续期不改变授权记录 ID；重新登录与管理撤销之间继续使用安全修订校验，避免自动续期不断导致管理员操作冲突。

异常处理：

- 已存在文件损坏、摘要或结构异常：受保护站点拒绝放行，未保护站点正常运行，控制台提供诊断；不把坏文件当作空配置重建。
- 明确写入失败：登录、撤销等同步操作保留上一个已确认快照，不返回操作成功；后台续期写入失败保留待落盘活动并提示持久化异常，暂停新的内存续期，已有授权仍按当前到期时间检查，修复后在未过期且修订一致时重试。
- 写入结果未知：冻结新授权操作，临时拒绝所有依赖动态授权的新请求，扩展现有存储待确认流程；管理员确认当前持久化结果后重建索引。不得在撤销结果未知时继续按旧记录放行。
- 重启：读取最后确认的 `lastAccessAt` 和 `expiresAt`，过滤过期或账号修订不匹配记录，不因重启重新计时。
- 文件缺失且已有受保护站点：拒绝放行并提示访问账号未初始化，不自动创建默认访问密码。

## 6. 登录与管理接口建议

### 6.1 业务入口专用处理

隐藏路径由网关内部处理，不映射到管理 API，也不把管理会话 Cookie 发给用户：

| 路径与方法 | 行为 |
| --- | --- |
| `GET <loginPath>` | 输出登录表单或当前 IP 授权结果，创建短期表单上下文 |
| `POST <loginPath>/login` | 校验独立账号，授权服务端解析出的来源 IP |
| `POST <loginPath>/logout` | 校验表单上下文，撤销当前来源 IP |

短期表单上下文与 IP、入口、CSRF 随机值绑定，最多 10 分钟、总量有界，只用于提交/撤销；认证成功后旋转上下文，不是控制台登录会话，也不能替代 IP 授权。新 GET 取得的上下文不得凭当前 IP 已放行直接获得撤销权限，撤销须使用此次已认证的上下文或重新验证访问密码。

密码通过 HTTPS POST 提交；表单 CSRF 令牌、精确 Origin 校验、SameSite Cookie 共同保护登录与撤销。Cookie 使用 Secure、HttpOnly 并限定隐藏路径，不跨域共享。不接受 GET 授权或撤销，不允许 CORS 通配来源。[登录也需要防护 CSRF](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)。

登录失败使用统一提示，按来源 IP 限制为每分钟 5 次尝试，同时设全局并发上限约束 Argon2 内存；无效账号也执行等价密码工作量。页面及响应设置 no-store、no-referrer、noindex 和禁止嵌入，不记录密码、完整隐藏路径、表单令牌或 Cookie。认证防护参考 [OWASP Authentication Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)，具体参数以本项目容量测试为准。

### 6.2 现有控制台认证之下的管理接口

| 接口建议 | 用途 |
| --- | --- |
| `GET /api/admin/v1/access-control` | 账号初始化状态、授权数量、存储状态；不返回密码摘要 |
| `PUT /api/admin/v1/access-control/account` | 初始化/更新独立账号，要求当前管理员密码再认证 |
| `GET /api/admin/v1/access-control/grants` | 分页查询授权记录 |
| `DELETE /api/admin/v1/access-control/grants/:id` | 撤销一个授权，携带预期修订防止误删重新授权记录 |
| `POST /api/admin/v1/access-control/grants/clear` | 清空授权集合，携带预期修订 |
| `POST /api/admin/v1/access-control/path` | 生成新随机路径，只返回候选值供草稿采用，不直接发布 |

管理接口继续使用既有管理登录、Host/Origin/CSRF 校验及审计；默认分页 50、最大 200。凭据更新不返回明文密码，不提供找回旧密码接口。

## 7. 发布校验与兼容性

当至少一个站点开启 `requireIpLogin` 时，发布必须满足：

1. 访问授权功能已配置，独立访问账号已初始化并处于可用状态，授权存储无异常。
2. 入口站点存在、启用且不在维护中，所选精确域名属于该站点，HTTPS 端口及证书有效。
3. 隐藏路径格式有效，入口命名空间不与站点已有路由冲突；根路径 `/` 兜底可保留，因为内部入口先于业务匹配。
4. 登录、授权校验与续期统一使用规范化后的 `RemoteAddr`，不增加来源模式切换选项。

仍有受保护站点时，不允许发布删除、停用或维护登录入口站点的配置，除非同次发布切换到另一个有效入口，或显式关闭所有站点的保护。

隐藏路径轮换只改变后续登录入口，不清空已有有效授权；清空是单独的即时操作。变更保护标记不删除原有 CIDR、路由或账号。独立访问账号在运行期被禁用时，已有授权全部失效，受保护站点保持拒绝状态，不自动取消站点标记。

旧配置、未开启标记的站点、管理登录和现有首次管理员初始化流程保持原有行为。上线本功能不自动创建账号、开启保护或发布用户站点。

## 8. 模块划分与实施顺序

| 模块 | 计划内容 |
| --- | --- |
| `internal/config` | 入口及站点标记字段，规范化、结构校验与发布影响 |
| `internal/accessgate`（新增） | 来源 IP 解析、独立认证、表单上下文、动态授权与有界内存索引 |
| `internal/store` / `internal/jsonfile` | 私有 JSON 原子持久化、修订冲突、待确认与恢复流程 |
| `internal/gateway` | 隐藏入口分派、动态校验、缓存控制、脱敏访问记录 |
| `internal/admin` | 凭据与授权管理、敏感操作再认证、审计事件 |
| `web/src` | 系统设置分区、站点开关和卡片按钮、独立登录页样式 |

实施按以下阶段完成，后续启动、构建与 Git 操作仍需单独授权：

1. 配置与私有存储：先完成 JSON 生命周期、账号修订、48 小时滑动续期、批量落盘、授权过期与撤销。
2. 网关与直连登录：实现隐藏页面、动态检查及与维护/静态策略的优先级。
3. 控制台：入口设置、站点标记、授权列表与发布校验。
4. 使用模拟站点、临时账号及证书做协议与浏览器验收，更新运维说明。开发环境、构建及 Git 操作继续按单独授权执行。

## 9. 验收清单

- 标记关闭时行为不变；开启后未授权返回真实 404，不跳转或泄露隐藏入口。
- 正确凭据仅授权实际来源 IP；伪造请求字段或转发头不能加入其他 IP。
- 同 IP 可访问全部标记站点；不同 IP、过期、撤销和账号变更后拒绝新请求。
- 使用可控时钟验证首次登录后 48 小时、有效期内访问后再延长 48 小时、持续活跃持续续期、恰好到期拒绝，以及 4xx/5xx、探测和登录页 GET 不续期。
- 覆盖跨站点共享续期、304/重定向、SSE/WebSocket 传输、过期长连接不能复活授权、撤销/清空与批量落盘并发、正常退出最终刷盘及异常退出的活动丢失边界。
- 静态白名单与黑名单不能被动态授权绕过；维护 503、未知 SNI 拒绝、HTTP-01、HTTPS 跳转和路由最长前缀逻辑符合上述顺序。
- 代理、静态、重定向、固定响应、WebSocket/SSE 的入口校验及缓存策略一致。
- 登录限流、统一错误、CSRF、并发密码校验、上下文过期、撤销权限和隐藏路径脱敏可验证。
- JSON 重启恢复、容量上限、写失败、结果未知、撤销与登录并发、账号改密原子清空、业务回滚不恢复授权可验证。
- 覆盖 IPv4、IPv6、映射地址、共享 NAT、来源端口变化及无效 RemoteAddr；伪造各种来源头不得改变登录、授权查询、续期或撤销所使用的 IP。
- 站点按钮只改本地编辑，未保存或未发布不生效；入口不可用时发布被拒绝，管理端仍可恢复配置。
- 中文页面、自定义开关/按钮/确认框、键盘操作和手机布局沿用现有标准。

第一版不包含多访问账号、按账号分配站点、MFA/OIDC、按设备识别、永久授权和撤销时强制断开存量连接。若这些属于实际使用要求，应先调整模型再实施。
